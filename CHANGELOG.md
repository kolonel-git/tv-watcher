Side effect: screen readers do not see the player controls (keyboard shortcuts unaffected). `run_tv_watcher.cmd` was also fixed: `call "flutter"` (quoted bare name) made flutter.bat fail with 'not a clone of the GitHub project'; it now resolves the full path and uses Windows line endings.

- Fix: subtitles could only be dragged sideways and sat mid-screen. Root cause: `Positioned`/`AnimatedPositioned` was nested under `LayoutBuilder`/`StreamBuilder`, where Flutter silently ignores it (it must be a direct child of a `Stack`). `SubtitleLayer` now owns its Stack and the player wraps it in `Positioned.fill`, so text sits at the chosen offset and drags freely on both axes. The subtitle layer is stacked above the control bar so it can be dragged even where the bar is. The lift above the bar applies only to the default position. New widget test wraps the layer exactly like the player. 229 tests.
- Subtitle settings are reachable only from the Subtitles page (footer row 'Subtitle settings'); the separate 'Subtitle appearance' entry on the settings root is gone and Back from it returns to Subtitles.
- Added `run_tv_watcher.cmd`: builds and launches the latest source with `flutter run -d windows` (r hot reload, R hot restart, q quit). A Desktop shortcut can point at it so a demo never runs a stale build.
- Build fix and cleanup: the 'wall of errors' was a stale CMake cache (install prefix stuck at C:/Program Files/tv_watcher after interrupted configures), not source code; clearing the cache fixed it.
